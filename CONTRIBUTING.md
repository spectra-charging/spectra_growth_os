# Contributing Guidelines

Welcome to the Spectra Growth OS development team!

These guidelines help maintain consistent code quality
and collaboration across the project.

## 1. Development Workflow

1. Understand the assigned task.
2. Create a feature branch.
3. Implement the changes.
4. Test your changes.
5. Commit your work.
6. Open a Pull Request.
7. Request a code review.

## 2. Branch Naming Convention

- feature/feature-name
- bugfix/bug-name
- docs/documentation-name
- refactor/component-name

## 3. Commit Message Convention

Use meaningful commit messages.

Examples:

- feat: add dashboard layout
- fix: resolve navigation issue
- docs: update project README
- style: improve dashboard design
- refactor: organize components

## 4. Coding Standards

- Write clean and readable code.
- Use meaningful variable names.
- Avoid unnecessary code duplication.
- Keep components reusable.
- Document important functions.
- Test changes before submitting.

## 5. Pull Request Guidelines

Every Pull Request should include:

- Clear description of changes
- Related issue number, if applicable
- Screenshots for UI changes
- Testing details

## 6. Security

- Never commit API keys or passwords.
- Use environment variables.
- Do not upload confidential company data.
